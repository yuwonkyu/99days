## 2. 플레이 검증

- [x] Day 1~99 풀 플레이 검증(2026-08-03, 브라우저 자동화로 production 24일 + local 34일 진행) — 기계적으로 확인 가능한 항목(종료 조건/계승/복귀 배너/폴백 전환)은 모두 확인 완료. 다만 오탈자·세계관 톤처럼 사람이 읽고 판단해야 하는 부분은 사용자가 한 번은 직접 읽어보는 걸 권장
- [x] **15~21일 구간 반복 버그 재현 여부 재확인**(2026-08-03) — 두 차례 플레이(1~24일, 1~34일)에서 동일 상황이 그대로 반복되는 사례는 없었음. 다만 "반복되는 느낌"의 실제 원인은 아래에서 발견한 day_summary 누락 버그로 인한 과도한 오프라인 폴백이었을 가능성이 높음(오프라인 시드는 40개뿐이라 AI보다 다양성이 낮음) — 수정 완료
- [x] 3가지 종료 조건 각각 테스트(2026-08-03): 체력 0(사망)/99일 완주/직접 포기 모두 로컬에서 localStorage 상태 조작으로 재현 확인, 엔딩 문구·"새로운 인생 시작하기" 버튼 정상 동작
- [x] 계승 시스템 실동작 확인(2026-08-03): "에일라"를 포기 처리한 뒤 새 캐릭터("세드릭")로 플레이하니 AI 응답에 "에일라라는 여자가 죽었다고..."로 실제 언급됨을 네트워크 응답에서 직접 확인
- [x] "복귀 요약 배너" 동작 확인(2026-08-03): `lastPlayedAt`을 4시간 전으로 조작 후 재접속 시 배너 표시 및 "확인" 닫기 버튼 정상 동작
- [x] Worker 응답 실패/네트워크 차단 상황에서 오프라인 폴백으로 자연스럽게 전환되는지 확인(2026-08-03) — 전환 자체는 정상 동작하나, **버그를 하나 발견해 수정함**: Worker가 200 응답을 반환해도 `day_summary`(또는 드물게 `stat_changes`)가 누락된 경우가 실측 약 40~50%에 달했고, 클라이언트의 `isValidAITurnResponse`가 이를 엄격히 거부해 멀쩡한 AI 응답을 버리고 오프라인 폴백으로 넘어가고 있었음(`worker/src/index.ts`의 `max_tokens: 500` 트렁케이션이 유력한 원인으로 추정). `src/engine/aiClient.ts`를 수정해 `situation`/`choices`만 필수로 남기고 `stat_changes`/`day_summary`는 누락 시 안전한 기본값(빈 객체 / outcome·situation에서 파생한 요약)으로 채우도록 완화 — AI 응답 활용률이 크게 개선될 것으로 예상

## 4. 콘텐츠 확장 (999/999 목표, 장기)

지금은 시드 59개(캐릭터 1명 기준 ≈300종+ 조합 렌더, 2026-08-06 기준) / 엔딩 62개. 아키텍처(시드+낱말뱅크,
무드×타입 그리드)는 이미 갖췄으니 이후 세션에서 아래를 반복하며 늘려나간다 — 매번 새로 설계할 필요
없이 항목만 추가하면 됨. **AI가 생성한 상황은 오프라인 시드로 자동 축적되지 않는다** — 시드는 손으로
저작한 고정 데이터이고, `usedSeedIds` 반복 방지도 캐릭터 1명(1판)에 한정된다.

**2026-08-06부로 우선순위가 올라감**: `AI_ATTEMPT_RATE`(0.15, 최초 0.1에서 심사 기간 대응으로 재조정)로
AI 호출을 15%로 제한하면서 오프라인 생성기가 사실상 주 경로(99일 중 ~84일)가 됐다 — 999 목표를
"언젠가"가 아니라 다음 세션에서 바로 착수할 항목으로 격상 고려.

- [x] "특정 시드(숲 발자국 미스터리)가 유독 자주 나온다"는 제보로 원인 확인: 성격/직업 가중치가 버킷 크기와 무관하게 카테고리 전체에 곱해지다 보니, 시드가 적은 버킷(예: outdoor/mystery 3개)일수록 개별 시드 픽률이 구조적으로 높았음. 최소 버킷(2~3개) 위주로 8개 신설해 대부분 4개 이상으로(2026-08-06) — 여전히 999 목표엔 한참 못 미치므로 계속 늘려나갈 것
- [ ] [situationSeeds.ts](../../src/data/situationSeeds.ts)에 버킷(모드×카테고리)당 시드 추가 계속 (현재 3~7개/버킷 → 목표 늘리기, outdoor/danger 7·outdoor/bond 3이 각각 최다/최소)
- [ ] `TIME_MOODS`/`STRANGERS`/`THREATS`/`OMENS`/`NOISES` 같은 낱말 뱅크 항목 확충 — 뱅크 하나 늘릴 때마다 해당 시드들의 조합 수가 곱으로 늘어남
- [x] 정적 감사로 "항상 똑같은 문장만 나오는" 시드 22개를 찾아 그중 15개에 `TIME_MOODS` 재사용으로 변주 추가(2026-08-06) — 남은 7개(`od-horror-3`/`sh-danger-2`/`sh-work-1`/`sh-mystery-1`/`sh-mystery-3`/`sh-horror-2`/`sh-bond-2`)는 이미 특정 시간대("밤길", "한밤중", "자다가")를 전제로 한 문장이라 `TIME_MOODS`를 그대로 못 쓴다 — 전용 소규모 뱅크(예: 야간 전용 시간 표현 2~3종)를 새로 만들거나 다른 변수를 찾아 후속 세션에서 처리
- [ ] 새 카테고리 후보 검토 (예: 가족/권력다툼 등) — 현재 7종(위기/생계/사교/수수께끼/공포/황당/호감)에서 확장
- [ ] [endings.ts](../../src/data/endings.ts)의 type×mood 셀마다 텍스트 추가
- [ ] 콘텐츠가 늘어날 때마다 `docs/design/04-ai-gamemaster-prompt.md`의 수치(시드/렌더/엔딩 개수)도 함께 갱신

- [ ] Worker 재배포 후 실제 AI 응답에서 `thread.status`가 기대대로 나오는지(특히 `continuing`이 가끔만 나오고 매번 튀지 않는지) 실플레이로 확인 필요 — 로컬 typecheck/오프라인 폴백 경로만 검증됐고, AI 경로의 실제 스레드 판단 품질은 Haiku 4.5 응답을 직접 봐야 알 수 있음
